# AI 本地知识库 — 项目介绍

## 项目背景

在日常开发和学习过程中，我们会积累大量的文档资料，包括技术文档、学习笔记、项目方案等。这些资料分散在不同的文件夹和工具中，需要时往往难以快速找到相关的信息。

AI 本地知识库（RAG Knowledge Base）就是为了解决这个问题而设计的。它利用大语言模型和向量检索技术，让你可以用自然语言提问，系统会自动从你的文档库中找到最相关的内容，并生成准确的回答。

## 核心概念：什么是 RAG？

RAG（Retrieval-Augmented Generation，检索增强生成）是目前大模型应用中最重要也最实用的技术范式之一。它的核心思想是：在大模型回答问题之前，先从外部知识库中检索相关信息，然后将这些信息与用户问题一起提供给模型。

这样做有几个关键优势：
- 模型可以回答训练数据中没有的最新信息
- 减少模型「幻觉」——回答基于真实文档
- 可以引用来源，答案可追溯、可验证
- 无需微调模型，只需更新知识库

## 技术栈选型

### 前端框架：Streamlit

Streamlit 是目前最流行的 Python Web 应用框架之一，特别适合数据科学和 AI 应用的快速开发。选择它的原因：
1. 纯 Python 代码，无需学习 HTML/CSS/JavaScript
2. 内置文件上传、聊天界面等组件
3. 与 Python 数据生态（Pandas、NumPy 等）无缝集成
4. 社区活跃，文档完善

### 向量数据库：ChromaDB

ChromaDB 是一个开源、轻量级的向量数据库，专为 AI 应用设计。选择它的原因：
1. 零配置运行，嵌入到应用中
2. 支持本地持久化存储
3. 内置多种距离度量（余弦相似度、欧氏距离等）
4. API 简洁直观

### 大模型 API

系统设计为 OpenAI 兼容接口，可以灵活切换不同的底层模型：
- DeepSeek：性价比极高的模型，中文能力强
- MiMo：小米自研大模型，覆盖文本、图像、语音多模态
- 其他兼容 OpenAI 格式的模型提供商

## 系统流程

1. **文档上传** — 用户上传 PDF、Markdown 或纯文本文件
2. **文本提取** — 系统解析文件，提取纯文本内容
3. **智能分块** — 按段落和语义边界将文本切分成适当大小的块
4. **向量化** — 调用 Embedding 模型将每个文本块转换为向量
5. **存储入库** — 向量和原始文本一起存入 ChromaDB
6. **用户提问** — 用户用自然语言输入问题
7. **语义检索** — 将问题向量化，在知识库中找到最相关的文本块
8. **上下文组装** — 将检索到的文本块与用户问题组合
9. **生成回答** — 调用 LLM 基于上下文生成准确回答
10. **来源追溯** — 回答中引用原始文档名称

## 应用场景

### 个人场景
- 学习笔记管理：将学习记录整理入库，随时提问回顾
- 技术文档查阅：项目文档、API 参考集中管理
- 阅读笔记沉淀：读书笔记、文章摘要统一检索

### 团队场景
- 团队知识库：产品文档、技术方案、会议纪要集中管理
- 新人入职：新成员可通过问答快速了解团队知识
- 项目交接：历史决策和讨论记录可检索

## 未来扩展方向

- 支持 Office 文档（.docx, .pptx, .xlsx）解析
- 多模态检索：支持图片、表格的内容识别和检索
- 知识图谱增强：将文档中的实体和关系构建为知识图谱
- Web 端抓取：自动抓取指定网页内容并入库
- 聊天记录导入：支持微信、飞书聊天记录的导入和检索
