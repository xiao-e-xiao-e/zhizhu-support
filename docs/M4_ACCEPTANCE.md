# M4 智能工作流

应用版本 2.4.0，数据库迁移 0004。M4 新增独立“智能助手”和“FAQ 知识运营”，现有知识问答、多轮改写及客服工单功能继续可用。公网发布仍需 M5 的运行保障和真实业务验收。

## 智能助手

进入“智能助手”，选择产品与版本，描述问题或提供工单 ID，点击“开始执行”。模型根据问题选择工具，界面实时显示步骤；完成后显示回答、证据、工单结果、耗时和用量。每个任务独立执行，不自动继承其他任务的历史；多轮对话仍使用“智能问答”。

| 工具 | 行为与权限 |
|---|---|
| search_knowledge | 检索 M3 已发布知识，沿用产品版本、停用及归档过滤 |
| search_resolved_tickets | 对最近 100 条符合权限的已解决/关闭工单做 BGE 语义排序；普通用户仅本人，客服可查团队 |
| get_ticket_status | 查询可访问的工单状态，无法访问时返回不存在；指定范围时不得跨范围 |
| create_ticket | 只准备待确认草稿，不创建工单；无写库授权来自模型参数 |

工具参数由 Pydantic 校验，额外字段、非法数量和未知工具均拒绝。模型不能指定用户、角色、模型地址、产品或版本。执行权限不会超过任务发起时的权限；客服降权后不能通过列表、详情或请求重放读取团队任务结果。助手记录仅本人可读，管理员也不能默认读取他人的私人助手任务；FAQ 生成记录属于客服知识运营，客服和管理员可查看。

模型准备工单后，页面显示明确的“尚未创建”提示。用户可修改标题、描述与优先级，核对绑定的产品版本后点击“确认提交工单”。确认有效期为 15 分钟；放弃、过期或失败的草稿不能提交。

确认后的工单归属于当前用户，工单和执行结果在同一事务提交。稳定幂等键保证重复确认只产生一个工单；重试提交不同内容返回冲突，避免误认为已经更新工单。工具本身不具有分配、关闭、删除工单或直接发布知识的能力。

## 执行追踪与恢复

AgentRun 保存任务状态、模型、范围、结果、用量、错误及重试关联；AgentStep 保存工具名称、合法输入、输出、耗时及状态，不保存或展示隐藏推理。模型调用也记录步骤，供应商专属参数只发给相应端点。

默认单次最多 6 次工具调用、4 轮模型调用、60 秒总时限，单次模型或只读工具等待不超过 15 秒，token 预算为 16000。模型输出受 max_tokens 控制；调用前按输入字符保守估算余量，调用后累计供应商实际用量。这是单任务资源边界，不是账单硬额度；跨用户限流和总费用控制属于 M5。

单个用户同时最多有一个待执行/运行中的助手任务。只读工具共用最多 4 个执行线程，超时后停止等待，其底层只读计算可能稍后结束，不会因此创建工单。重复的相同工具参数在单次运行中复用结果。

排队任务和结果保存在数据库。页面取消会提交取消请求；断开的执行连接会尽力取消。进程异常退出后，超过截止时间的运行在下次读取时标记失败，用户可显式重试，新任务关联旧任务。系统不会在重启后自动重放有待确认的写操作。

## FAQ 知识运营

1. 客服打开有解决说明的已解决或已关闭工单，点击“生成 FAQ 草稿”；模型不可用时可用“人工整理 FAQ”。同一工单只保留一个 FAQ 编辑入口，重复点击返回现有草稿。
2. 模型依据问题及解决说明起草问答，原始会话不自动公开。常见邮箱、手机号和凭据先脱敏，模型输出再做同类处理；其他客户标识和领域隐私仍须人工核对。
3. 客服编辑问题与答案，提交审核。管理员填写意见，可退回修改；批准前需要明确核对事实、适用范围及敏感信息。
4. 批准后，在同一 SQL 事务创建 M3 原件修订与后台任务，进入“审核通过，入库中”。处理失败可重试，入库成功仍不会自动发布。
5. 管理员点击“发布 FAQ”，将 FAQ 状态与知识修订发布一起提交。之后普通用户才能通过知识检索和问答使用这份内容。
6. 已发布 FAQ 可“修改为新草稿”，再次编辑、审核和发布。旧发布版本继续可用，新草稿和失败修订不覆盖它；历史知识修订仍可在文档管理回滚或撤回。

原工单重新打开、解决记录改变或分类改变时，旧草稿不得直接审批/发布，应重新核对最新解决说明。草稿、原问题快照、审核意见和生成记录只对客服开放；发布文件仅包含审核后的问题与答案，不包含工单原始会话、来源快照和操作人信息。

FAQ 页面同时提供“未解决问题线索”，按未解决反馈中的相同问题聚合，展示频次最高的 20 项及已关联工单数；这只是运营线索，不代表确认的缺陷。

## 验证结果

| 检查 | 结果 |
|---|---|
| SQLite / PostgreSQL 17 全量回归 | 各 81 项通过 |
| 写操作确认、幂等及并发 | 模型只产草稿；重复/并发确认仅一个工单；事务中断不留下半提交工单 |
| 工具权限、未知参数和范围 | 越权工单、未知工具及身份字段注入拒绝；权限变更不扩大旧运行能力 |
| 恢复与预算 | 模型失败、工具超时、取消、过期、步数及 token 预算验证通过 |
| FAQ 审核、版本及原子发布 | 未解决工单不生成；退回、冲突、原记录重开、入库及发布门禁、发布失败回滚通过 |
| TypeScript / Vite、Ruff、迁移一致性 | 通过；前端仍有主包体积告警 |
| 隔离 Docker 与 Edge | 真实工具 SSE、用户核对建单、重复确认、用户隔离、FAQ 模型生成/编辑/审核/后台入库/发布及 API 重启持久化通过 |
| 页面 | 桌面助手、确认卡、FAQ 审核发布及 390 像素宽度助手已检查，无页面脚本错误 |

接口回归中的模型使用替身，不消耗远程额度。真实验证另使用配置的模型和本地真实 BGE 嵌入，只有隔离的合成用户、资料与工单。

真实模型工作流首轮为 10 个场景，自动评分 9/10；唯一失败是拒答措辞检测漏判，实际没有编造价格或支付方式。原始记录和分数保留，开发代理复核单独记录。所有场景均未自动写工单、未返回他人工单标记、未跨产品版本检索；显式确认重放仅生成一条工单，FAQ 生成到发布链路通过。模型用量为助手 22,853 token，FAQ 292 token；浏览器实际调用为独立验收用量，未合并到此固定报告。

## 接口与部署

| 接口 | 用途 |
|---|---|
| POST / GET /api/agent/runs | 创建待执行任务 / 本人任务分页 |
| GET /api/agent/runs/{id} | 持久化结果与步骤 |
| POST /api/agent/runs/{id}/stream | 执行助手并以 SSE 返回 run、step、done |
| POST /api/agent/runs/{id}/execute | 非流式执行，同一任务不重复领取 |
| POST /api/agent/runs/{id}/cancel、retry | 取消 / 显式创建关联重试任务 |
| POST /api/agent/runs/{id}/confirm-ticket | 本人显式确认提交，需 confirmed=true |
| POST / GET /api/faqs | 从已解决工单创建 / 客服列表 |
| GET / PATCH /api/faqs/{id} | 草稿详情 / 带 revision 编辑 |
| POST /api/faqs/{id}/generate、regenerate | 执行已排队模型生成 / 准备重新生成 |
| POST /api/faqs/{id}/submit、review、publish、revise | 提交、审核、发布及退回编辑 |
| GET /api/faqs/gaps | 未解决反馈聚合线索 |

API 启动时迁移至 0004，不新增外部服务，继续使用原有五服务部署。调整 AGENT_MAX_STEPS、AGENT_MAX_ROUNDS、AGENT_TIMEOUT_SECONDS、AGENT_CALL_TIMEOUT_SECONDS、AGENT_TOKEN_BUDGET 可改变单任务边界；已有 .env.deploy.local 不需要覆盖。

M5 仍需 HTTPS、配额与限流、依赖审计、容量压测、备份恢复演练和业务专家的真实资料验收。当前不提供跨企业租户隔离、外部系统写入、自动发布 FAQ、生产账单硬额度及业务级隐私自动识别保证。

工具协议参考供应商的 [Tool Calls 文档](https://api-docs.deepseek.com/guides/tool_calls/)，模型仅提出调用，具体工具和授权由服务端实现。
