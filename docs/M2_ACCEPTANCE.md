# M2 客服业务使用与验收说明

M2 已实现产品与版本范围、回答反馈、工单处理及审计记录。本工作区使用 http://127.0.0.1:8088，API 版本为 2.2.0，数据库迁移版本为 0002。

## 使用流程

1. 使用现有管理员登录，在“账号设置”创建客服与普通用户。没有内置客服或用户测试账号。
2. 在“产品与版本”中添加产品、版本。在“文档管理”上传时选择产品版本，或给已有资料调整分类。
3. 用户在“智能问答”选择适用的产品版本并提问。完整回答自动保存；修改会话名后可另存为副本。
4. 回答下面选择“有帮助”或“未解决”。未解决时可填写反馈，并继续“提交并转工单”；也可以在“我的工单”直接新建。
5. 提交前核对标题、描述、产品版本和优先级。勾选附带对话时，将最多 12 条、总计最多 16000 字符的对话副本提供给客服，每条最多 4000 字符；可以取消勾选。
6. 客服在“工单工作台”接单或分配处理人，回复建议，填写解决说明并标记已解决。
7. 提交者确认关闭，或者说明仍未解决并重新进入处理中。客服不能替其他提交者确认关闭；关闭后不能继续回复或改派。
8. “回答反馈”展示反馈原因、当时回答及关联工单。普通用户仅能看到自己的反馈，客服和管理员可以查看团队反馈。

## 状态与权限

| 操作 | 提交者 | 客服及管理员 |
|---|---|---|
| 创建工单 | 可以 | 可以 |
| 查看、回复工单 | 本人工单，关闭后不能回复 | 团队工单，关闭后不能回复 |
| 分配处理人 | 不可以 | 可分配给有效客服或管理员 |
| 开始处理、标记解决 | 不可以 | 可以，标记解决必须填写说明 |
| 已解决后重新打开 | 本人工单 | 可以 |
| 确认关闭 | 本人工单 | 仅自己提交的工单 |

变更使用 revision 校验，过期版本返回 409。创建工单使用提交者与幂等键的唯一约束，同一请求重复提交只生成一个工单；同一个键用于不同内容会被拒绝。

## 知识范围和历史记录

- 产品版本传入向量检索过滤条件。指定版本后仅召回对应资料；未指定版本时允许检索该产品多个版本，未指定产品时检索全部共享资料。
- 停用后不能再选作新问答和工单的范围，历史记录仍保留。文档发布和完整原文版本管理在 M3 实现。
- 当前文件名仍全库唯一。不同产品或版本请使用不同文件名，跨范围同名上传会被拒绝；已有文件可以主动调整分类。
- 会话中途切换范围需要开始新会话。完整回答自动保存，异常或中断的部分回答可能需要手动保存。
- 再次保存未变化的会话会保留消息 ID 和反馈。删除会话或重新生成后，已提交的工单副本和反馈快照保留。

## 验证结果

- SQLite 与 PostgreSQL 17 各通过 39 项测试，覆盖 M1 回归、越权、状态和版本冲突、并发幂等、反馈、迁移数据保留及 Chroma 范围过滤。
- TypeScript、Vite 和 Docker 镜像构建通过。
- Edge 走通产品版本创建、资料分类、问答、反馈、附带对话建单、客服接单回复解决、提交者关闭及越权拒绝。
- 独立 Docker 项目验证完整业务链路、API 重启后的记录持久化，以及删除会话后副本仍保留。
- 问答业务验收使用生成替身；Chroma 测试使用固定向量和真实向量库，不调用远程 LLM。真实模型质量评估在 M3 继续实施。

## 部署与数据保留

本工作区已更新到 M2。迁移前保存 PostgreSQL 备份和旧镜像标签，位置在 backend/storage/backups，未加入 Git。现有账号保留，未向实际部署插入测试工单或测试账号。

其他环境升级前先备份数据库，再执行：

```powershell
docker compose --env-file .env.deploy.local up --build -d --wait
```

原生 Python 环境需要先在 backend 下执行 `python manage.py migrate`。回滚需要让数据库版本与旧镜像中的 Alembic 迁移一致；保留升级后的数据前不要直接运行降级或覆盖数据库。
