# 知助：业务账号与产品资料

当前版本：2.6.1，数据库结构：0007。

## 日常使用

通过普通登录表单输入团队管理员发放的账号与密码。登录页不展示账号清单、公共密码或一键角色入口。网站不设置独立体验模式。

| zhao.ning | 管理员 | 账号授权、产品与版本、文档发布、FAQ 审核 |

每个账号使用独立随机密码，未写入前端或仓库。管理员通过“账号设置”创建账号并设置可访问产品。选择“仅访问指定产品”但不分配产品时，该账号无法访问任何产品资料；选择“全部产品”时按角色访问现有产品。用户可自行修改密码，更新后所有设备会话失效。

用户在“产品资料”查看已发布内容，进入“智能助手”选择产品与版本提问；回答可以展开来源。该聊天入口统一承接知识查询、相似工单检索、工单进度查询和草稿准备，支持连续追问，记录自动保存。自己的会话、反馈与工单遵循原有归属权限。智能助手可准备工单草稿，核对并确认后才提交。

## 资料管理

新增 11 份业务说明文件在 `backend/business_documents/`，另有 1 份已发布的成员邀请 FAQ。文档通过原件存储、后台解析与向量化、审核发布流程入库；同名同范围的新文件产生新修订。文档描述 Atlas 与 Orion 的产品支持规则，客服工作台自身的上传限额以运行配置为准。

账号产品权限在服务端生效，涵盖产品目录、文档列表与统计、分块阅读、检索、同步与流式问答、助手知识工具。修改请求参数不能访问未授权产品。原有账号默认保持原访问范围，管理员可以在正常管理页面继续配置。

## 从先前版本迁移

先停止写入并备份 PostgreSQL、Chroma、原件卷及旧镜像，升级数据库并保持 `DEMO_MODE=false`。仅曾使用旧初始化工具、且资源已明确登记归属的环境可以运行：

```powershell
docker compose --env-file .env.deploy.local exec -T api python manage.py prepare-business
```

该命令将登记的四个初始账号转换为普通业务账号、轮换密码并撤销旧 Cookie；不接管同名现有账号。私有凭据首次生成于容器 `/app/storage/business-accounts.json`，后续运行不会重置密码。原有非登记账号与数据保留。

旧原件和执行追踪保留内部记录并退役，不重写其文件哈希；退役修订不参与检索、阅读、回滚和下载。新的业务文档重新入库发布，对话回答重新调用配置的模型生成，保留消息 ID 与工单关联；引用登记旧资料的四个转换账号的个人历史也刷新对应回答。原工单快照随之更新。已失去产品权限的历史会话保留原始记录，但列表、查看、导出和继续提问均不再提供访问。重复运行跳过已完成资源，避免覆盖后续业务编辑。

全新部署应使用 `create-admin` 创建管理员，通过账号管理、产品管理和文档上传完成业务配置；不要运行旧夹具初始化。


## 统一助手对话

网站只保留一个“智能助手”入口。每次回复可以调用资料检索或业务工具，处理过程默认折叠。需要人工协助时，助手在原对话中展示可编辑的工单草稿，点击确认后才建单；提交后继续询问“刚才的工单什么状态”，助手会读取实际状态。

“有帮助”“未解决”和“转为工单”保留在回答下方。工单创建时关联当前对话、回答 ID 及上下文快照。对话中的工具回复与普通回答统一展示，历史支持继续聊天、重命名及导出。重命名保持消息 ID、反馈与工单关联不变；旧问答记录原样保留，原助手执行记录按真实结果补入历史。

每个账号的产品范围、会话归属与工单访问限制继续生效。历史或客户端输入不会改变工具的执行身份。工单草稿具有确认期限，超时、取消、删除对话或权限变更后不能继续提交；连接中断可从历史查看状态并重试。
