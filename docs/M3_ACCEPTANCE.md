# M3 知识与问答质量

2026-10-26 实现后台入库、文档修订发布、多轮查询改写及真实模型评估。应用版本 2.3.0，数据库迁移 0003。本机入口为 [智能客服工作台](http://127.0.0.1:8088)。本版本完成本地验收，公网部署仍需 M4、M5。

## 业务使用

1. 客服或管理员进入“文档管理”，选择产品与版本后上传资料。支持 TXT、Markdown、PDF、DOCX、HTML 和 CSV；最多 10 个文件，默认每个不超过 20 MB。
2. 上传返回 202，原件及校验和保存后进入数据库任务队列。页面自动更新等待、处理进度、尝试次数及错误。扫描 PDF 需要先在外部 OCR 提取文本。
3. “版本管理”可查看修订分块、下载原件及操作记录。入库成功后状态为“待发布”，普通用户和问答均不可见。
4. 管理员审核后点击“发布”。同一文档最多一个已发布修订，新上传和入库失败均不影响现有发布。
5. 发布新修订后，历史修订可一键回滚。撤回或归档立即退出后续检索；恢复归档仍需重新发布。归档保留原件、向量及审计记录。
6. 相同产品、版本、文件名形成一个逻辑文档；相同内容和分块参数自动去重。不同产品或版本允许同名文件。已发布资料必须先撤回，才能修改分类。

客服可上传、查看历史、重试失败任务和调整未发布文档分类；发布、撤回、回滚、归档和恢复由管理员执行。普通用户仅能查看有效产品范围内的已发布资料。前端隐藏按钮之外，服务端也执行权限校验。

## 运行机制

Compose 包含 Web、API、PostgreSQL、Chroma 和 worker。队列使用 SQL 原子领取和带令牌的租约，长任务定期续租；旧租约不能提交结果。进程退出或机器重启后，超时任务可被重新领取。默认最多自动处理 3 次，失败后提供人工重试，并保留累计尝试次数。错误有指数退避；人工重试追加 3 次机会。

原件以修订 UUID 保存，处理前验证 SHA-256；向量按修订写入，重试使用稳定 ID 幂等 upsert。只有向量数量校验通过后才标记“待发布”。SQL 发布状态决定检索资格，所有用户检索和 RAG 都经过此过滤；修改分类不需要重新计算向量。

发布、回滚及分类变更使用文档 revision 防止并发覆盖。前端每 4 秒更新任务状态；worker 每 15 秒写心跳，60 秒无心跳提示离线。任务进度为处理阶段进度，不是剩余时间预估。

原生开发必须让 API 和独立 worker 使用同一 HTTP Chroma 服务，不应让多个 PersistentClient 进程共用本地目录。`manage.py adopt-legacy` 可重复登记旧资料，保留原始向量，不伪造缺失原件。Compose 在 API 启动前执行登记。

## 查询改写与问答

存在历史时，由服务端模型将当前问题补全为独立检索问题；最多使用最近 6 条消息、4000 字符历史。改写只接受包含单个 query 字段的 JSON，输出最多 512 字符，超时或无效响应回退原始问题。产品和版本范围由服务端独立传递，不受改写输出控制。

回答只使用本轮已发布证据，引用包含修订 ID 和修订号。SSE 提供 retrieval 事件及完成时的检索耗时、首字耗时、总耗时和 token 用量。前端提供“本轮检索问题”展开项，历史会话仍保留证据片段及修订身份；检索过程指标目前不单独持久化为业务运行追踪。

DeepSeek 请求默认显式关闭 thinking，避免短输出预算被隐藏推理消耗导致空回答。其他 OpenAI 兼容端点不接收该供应商专属参数。生成为空会报错；改写失败不阻断原始检索。

## 真实模型评估

评估使用已配置的 deepseek-v4-flash 和本地 BAAI/bge-small-zh-v1.5，真实执行入库、发布、检索、改写及生成。评估库和原件目录独立，不读取业务会话。

固定数据集包含 20 份合成资料、60 题：20 题直接问法、20 题同义问法、8 题多轮指代、8 题无答案、4 题用户提示注入。两套产品版本具有冲突政策数值，以检查版本隔离。4 题标为 development，其余 56 题为 acceptance；本轮没有针对结果调整提示词或重标答案，但目前只有这一组合成资料，并非独立真实业务盲测集。
